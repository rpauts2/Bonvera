# Итоговая проверка сборки Cashback Bot

Дата проверки: 14.11.2026

## Что проверено автоматически

- `python -m compileall -q bot alembic` — успешно.
- Alembic revision graph — одна голова `0004_offer_audit`; все четыре миграции образуют единую цепочку.
- `pytest -q` — **21 passed**.
- Каталог — 93 уникальных оффера: карты 16, букмекеры 6, МФО 52, CPL 19.
- 93 индивидуальных JPG-файла найдены; SHA-256 всех файлов уникален.
- Тесты проверяют возрастные диапазоны, выплаты/холды, уникальные коды, чек-листы доказательств, обязательную отправку комплекта, досылку дополнительных материалов и правила clawback для запросов на вывод.

## Доказательства по типу оффера

- Карты: личный кабинет/карточный продукт с ФИО для сверки и выпуском/активацией; если ЦД содержит покупку или расход — отдельная операция с датой, суммой и торговой точкой; для платного выпуска — отдельное подтверждение оплаты.
- МФО: два обязательных файла — ЛК с полным ФИО и статусом «Одобрено», затем подтверждение фактической выдачи с датой и суммой. Одобрение без перечисления займа не подтверждает ЦД «выдача займа».
- БК: профиль с идентификацией, история депозитов и рассчитанная квалифицирующая ставка; если конкретная акция отдельно требует начисления фрибета, потребуется дополнительный экран его начисления.
- CPL: подтверждение принятой/валидной заявки или привязки карты по ЦД. Само оформление займа не требуется, если ЦД этого не говорит.

Во всех чек-листах указано скрывать паспортные сведения, дату рождения, адрес, телефон, полные платёжные реквизиты, номера договоров и любые коды. Бот не просит CVV/CVC, PIN, пароль, OTP/SMS-код, фото всей карты, паспорт или полный договор займа. ФИО остаётся видимым только на том подтверждении, где нужна сверка владельца.

## Исправления финансовых сценариев

- При отзыве лида ожидающие запросы на вывод отменяются и резервируется/возвращается ровно одна компенсирующая проводка.
- Уже обрабатываемые выводы переводятся в `review_required`; администратор обязан сверить факт банковского перевода и только затем отметить выплату или отклонить запрос с возвратом.
- Повторное подтверждение одной сделки защищено блокировкой и уникальным ключом финансовой проводки.
- Окончание холда не начисляет деньги автоматически: администратор получает одно уведомление и выполняет финальную проверку.
- Запрос дополнительных доказательств требует нового файла, загруженного после запроса.
- Повторно присланный комплект по сделке в холде снова появляется в очереди; уже рассмотренный комплект не дублируется.
- Существенное изменение ссылки/условий/выплаты/холда букмекера сбрасывает письменное согласование.
- Изменения каталога пишутся в отдельный журнал с администратором и временем; реальные affiliate URL-токены не копируются в текст аудита.

## Не проверено в этой среде

Для postback endpoint access-log выключен, чтобы query-string секрет не попадал в стандартный журнал HTTP-запросов. Полный интеграционный запуск не выполнялся: в контейнере проверки отсутствуют `aiogram`, `aiosqlite`, `asyncpg`, `redis`, `APScheduler` и `ImageHash`; Docker/PostgreSQL/Redis и токен реального Telegram-бота недоступны. Поэтому пока нельзя утверждать, что polling, миграции на реальной БД, получение файлов из Telegram, postback-и конкретной партнёрской сети и реальные банковские переводы прошли полевую проверку.

Перед эксплуатацией нужно установить `requirements.txt`, запустить Docker Compose, применить Alembic на чистой и/или существующей БД, проверить все callback-и Telegram, протестировать idempotency postback-ов и провести безопасный тестовый вывод.

## Оставшиеся бизнес-зависимости

- В пользовательском списке URL есть только у 6 БК; для остальных 87 офферов ссылки должны быть добавлены администратором. Без ссылки бот блокирует создание сделки.
- Все 6 БК должны получить письменное разрешение рекламодателя/сети на cashback-формат и конкретный источник трафика; только после этого оффер переводится в согласованный статус.
- Автоматические выплаты по API не подключены; сейчас администратор вручную подтверждает фактический перевод.
- Проверка возраста — само-декларация (количество полных лет), не документальная идентификация.
- Скриншотные доказательства содержат персональные/финансовые данные. Нужны политика хранения и удаления, ограничение доступа администраторов и срок хранения файлов.
